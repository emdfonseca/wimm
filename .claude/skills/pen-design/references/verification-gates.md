## 10. Ready-for-build checklist

Mark each item Pass, `N/A — reason`, or Fail. "Not tested" is not Pass.

- [ ] Project Setup Record reflects current scope; open decisions do not block this scope.
- [ ] Goal, entry point, primary success path, and success outcome are explicit.
- [ ] Important alternative, failure, and recovery paths are drawn as branches; cancel/back/exit behavior is clear.
- [ ] Loading, validation error, server error, empty, and permission states exist beside their step where material.
- [ ] Destructive actions have a confirmation or undo model naming the affected object.
- [ ] Each adopted regime (Compact / Medium / Wide) has a composition or a recorded shared-structure mapping; frame widths and boundaries are recorded.
- [ ] `Device` values are assigned where Device-aware variables are used; flex/Hug/Fill is intentional.
- [ ] Semantic variables only; representative screens checked in Light and Dark; focus, error, disabled, overlay, and elevation stay legible in both.
- [ ] Active navigation state is visible; breadcrumbs, tabs, steppers, and Back each represent the correct relationship.
- [ ] Every overlay is classified inline / modal / drawer (modal or non-modal) / full page, and route-backed or ephemeral.
- [ ] Keyboard completion, focus order and transitions, non-color error cues, and required announcements are specified; §5.1.5 thresholds are met.
- [ ] Shared controls are library instances; no detached copies; instance overrides are intentional; reusable new solutions are flagged for promotion.
