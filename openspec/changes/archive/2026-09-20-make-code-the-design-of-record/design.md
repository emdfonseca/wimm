## Context

See proposal.md for why, and its Trial for the evidence. What shapes the
approach:

- The pen workflow is wired in six places: `openspec/schemas/wimm/schema.yaml`
  (the `canvas` artifact, lines 267-396, almost all pen, and three rules in
  `tasks`), `openspec/config.yaml` (context and the apply and archive
  guidance), `CLAUDE.md`, the root `justfile` (`pen-save`, `pen-import`,
  `pen-exec`, `pen-exec-test`, `pen-manifest`, `pen-verify-tokens`, and
  `pen-exec-test` inside `ci`), `packages/ui/justfile` (`gen` and `test`), and
  `.mcp.json`.
- Four scripts depend on frames: `gen-canvas-contract.py` reads the `.pen`
  files and writes `src/canvas-contract.json` (96 frames, 597 strings);
  `check-canvas.py` holds a 50-entry frame-to-file map and 17 accepted
  divergences; `test-contract.py` and `test-canvas.py` are their must-fail
  suites. Nothing else reads the contract.
- `check-geometry.py` reads only CSS and Svelte. Its numbers were copied from
  a canvas.md once and it has no `.pen` input.
- `check-stories.py` already refuses a component with no story. 97 of the 105
  page stories have a play function, and the page stories assert copy with
  `getByText`; they run in `just test apps/storybook`, which is in `just ci`.
- `design/tokens.json` is exported from the library by hand (ADR 0003).
  `pen-verify-tokens` and `pen-manifest` are in no check.
- `app/screen-layout` has a requirement that a screen matches its frame.
- `make-overview-a-useful-dashboard` is unapplied and has five tasks that edit
  the library, the contract generator and the frame map.
- The `openspec-propose` skill is generated by OpenSpec and forbids editing
  project code while planning. `.claude/skills/` is outside what a sandboxed
  session may write.

## Language

- **Design of record** — a page's presentational Svelte component and its
  stories. Never a drawing, a frame or a mock.
- **State story** — one story showing one state of a screen on fixtures.
  Never "frame", which no longer names anything in this repo.
- **Design canvas** — the page at `/canvas/index.html` in Storybook where
  state stories are seen at real sizes. Never "the canvas" alone in new text,
  and never pen.dev.
- **State plan** — what `canvas.md` holds: the state stories a change will
  write, the words each shows, and what was seen when they were looked at.
  The artifact keeps the id `canvas` because the graph and every archived
  change use it.
- **Flow** — as `add-design-canvas-flows` defines it. It replaces the
  journey; journey IDs are not issued any more and are never reused.

## Goals / Non-Goals

**Goals:**

- One copy of every screen. Nothing compares a screen with a picture of it.
- Every guarantee a frame check gave is either carried by a named check or
  named as dropped. None disappears silently.
- A change proposed the day after this lands never mentions pen.

**Non-Goals:**

- Image comparison of stories. ADR 0020's reasoning against it stands.
- Changing the design canvas. One row per story with sizes across is its own
  change.
- Rewriting archived changes. Their canvas.md files name frames that no
  longer exist, and an archive is a record, not a reference.

## Decisions

**`canvas.md` is a state plan written while planning, and the looking happens
in apply.** Planning may not edit code, and a story is code. So the artifact
names the state stories to be written, the fixture each needs, the words each
shows, the flow they join if any, and the components missing. Tasks then run
in a fixed order: components, the presentational screen with its state
stories, a look task, wiring. The look task opens the stories on the design
canvas at all four regimes, and writes what was seen and what changed back
into canvas.md under Seen. Wiring tasks come after it and never share a task
with it. *Alternative:* let the `canvas` artifact write the screen and stories
during planning, which is what the proposal first sketched. Rejected: it
breaks the planning boundary of a skill this repo does not own, and a plan
that has to be reviewed by running it is not a plan.

**The words are decided in the state plan and held by play functions.** Each
state story asserts the headings, labels and messages of its state with
`getByText` or a role query. `check-stories.py` gains one rule, every story
under `pages/` has a play function, with a must-fail case in
`test-stories.py`. It cannot see whether the play function asserts copy; that
stays a review matter, and the ADR says so. *Alternative:* keep
`canvas-contract.json` as a hand-edited list. Rejected: it is the second copy
under another name, and the 17 accepted divergences show how it ages.

**Coverage is moved before the contract is deleted.** One task reads the
contract against the page stories and lists, per screen, the notice titles,
notice bodies and failure messages no play function asserts. Those are the
strings ADR 0020 found reinvented. Each gets an assertion or a line saying
why not. Titles, ledes and field labels are already asserted where a story
exists for the state. Only then do the four scripts and the contract go.

**`check-geometry.py` stays, as a CSS check.** Its comments and messages stop
citing the canvas. Its numbers are now the record, not a copy of one.

**The pen files and tooling are deleted, not parked.** The five journey
files, `product-ui.lib.pen`, `library-manifest.tsv`, six `bin/` files, six
`just` recipes, `pen-exec-test` in `ci`, the `pen-design` skill, the pencil
entry in `.mcp.json`, and `docs/design/canvas-audit.md` and
`library-conventions.md`. `git log` is the archive. *Alternative:* keep the
files for sketching. Rejected by the owner: an ungated file next to the code
still gets read as a decision.

**`design/tokens.json` is the source of token values.** Nothing exports it
any more. `docs/design/tokens.md`, `packages/ui/justfile`, `package.json` and
the comments in `gen-tokens.py` and `check-tokens.py` say so. The validation
ADR 0003 describes is unchanged; only its person-verified library agreement
has nothing left to agree with.

**One ADR, 0023, and status lines on the ones it touches.** It supersedes
0020 whole, the drawing in 0008, and 0009, 0010 and 0011 whole, and the
library clause of 0003. Status lines follow ADR 0018's precedent, for example
`Accepted; superseded by 0023` and `Accepted; drawing superseded by 0023`,
because `adr-index.py` prints the first line of Status and the index is what
a session reads. 0008's artifact and its components-first rule survive.

**A component missing is two deliverables.** The Svelte component and its
story. The search-before-adding rule stays and points at `packages/ui/src`:
find where the design system already shows that data, open the candidates,
say why each cannot carry it.

**`make-overview-a-useful-dashboard` is rewritten with
`openspec-update-change`, as a task here.** Its canvas.md becomes a state
plan and its library, generator and frame-map tasks go. Done last, against
the new schema, so it is written once.

## Risks / Trade-offs

- [Copy coverage falls from 597 checked strings to what play functions
  assert] → The coverage task above, and the new play-function rule. Named as
  a reduction in ADR 0023 rather than claimed as parity.
- [Intent with no code cannot be recorded] → The state plan holds words and
  states; a presentational screen on fixtures is the sketch. Accepted.
- [`.claude/skills/` cannot be written from the sandbox] → The two skill
  tasks say so and are run with the owner's approval or by hand.
- [A deleted `.pen` is wanted later] → `git show <commit>:<path>` restores
  it, and ADR 0023 names the last commit that has them.
- [The schema edit breaks `openspec instructions`] → A task runs
  `openspec instructions canvas` and `tasks` on a scratch change and
  `openspec validate --all --strict` before anything is deleted.

## Migration Plan

Order is the rollback: coverage and the new check first, schema and docs
second, script removal third, file deletion fourth, ADR and index fifth, the
Overview change last. Each group leaves `just ci` green, so the change can
stop after any group. Rollback is `git revert` of the deleting commits.
